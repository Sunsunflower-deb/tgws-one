# История изменений

Формат: `## [версия] — дата`, далее короткий список изменений.
CI берёт раздел текущей версии и подставляет его в описание релиза.

## [2.2.0] — 2026-11-26

- **Fake TLS (`ee`-секрет) портирован целиком** из upstream `proxy/fake_tls.py`: проверка HMAC ClientHello и
  окно метки времени (защита от повтора), сборка ServerHello + ChangeCipherSpec + одной ApplicationData-записи,
  HMAC в поле random ServerHello, зеркалирование гибридной группы x25519mlkem768, обмен внутри
  ApplicationData-записей. С включённой маскировкой ссылка выдаётся с `ee`-секретом и доменом в hex.
- **Маскировка включена по умолчанию** под `www.microsoft.com`: сайт доступен без обхода, отвечает обычным
  TLS 1.3 и не выделяется в трафике. Своя ссылка `ee`-секрета показывается в окне; прежняя `dd`-ссылка
  продолжает работать (примерно одно соединение из 256 начинается с байта 0x16 и обрабатывается как
  маскированное, клиент переподключается). Выключить маскировку — пустой `faketls=` в `TgwsOne.ini`.
- **Маскировка стала fail-closed.** Непроверенный ClientHello уходит на маскировочный домен; если тот
  недоступен, клиент получает TLS alert (`handshake_failure`), а не молчаливое закрытие. Молчаливый обрыв был
  ровно тем признаком, по которому активное зондирование отличает прокси от настоящего сайта.
- **Маскировочный домен управляет fronting'ом**, зашитая строка `sprinthost.ru` убрана: без домена fronting не
  пробуется. Простаивающие сокеты пула пингуются с джиттером (`--ping-interval`, `--ping-jitter`; по умолчанию
  25 с + случайные 0–10 с в masked-режиме) — иначе долго молчащий сокет сам становится признаком.
- **Набор стратегий «Авто» задаётся по провайдеру**: файл `<провайдер>.rotation` в папке стратегий службы
  перечисляет, какие встроенные стратегии перебирать, ключ `provider` в `service.ini`. Неизвестный провайдер,
  пустой или нечитаемый файл дают универсальный набор — опечатка не оставляет машину без обхода.
- Настройка маскировки — `faketls` в `[proxy]` (`TgwsOne.ini`), домен вида `www.example.com`.

## [2.1.1] — 2026-11-26

- **Исправлено: в узкой области обхода («только Telegram») прокси оставался без защиты.** Запасной путь идёт не на
  хосты из `telegram.txt`, а на `kws<dc>.<домен>` за Cloudflare, и этих имён в узком списке не было. Где прямой
  маршрут к дата-центрам закрыт, а Cloudflare режется DPI, TLS до него рвался, WebSocket не открывался, и прокси
  отвечал `CF proxy failed: … timed out` — ни одного рабочего маршрута наружу. Теперь узкая область обходит и узлы
  запасного пути, остальные приложения по-прежнему не затрагиваются.
- Служба собирает `lists/cfproxy-hosts.txt` из `lists/cfproxy-domains.txt` и обновляет его перед каждым запуском
  обхода. `cfproxy-hosts.txt` — сгенерированный файл (перезаписывается), править нужно `cfproxy-domains.txt`; список
  доменов совпадает с запасным набором движка, за этим следит тест.
- Область «все приложения» не менялась: в ней обходятся все подсети Cloudflare, как и раньше.
- Ограничение: свои домены CF (`cfdomains`, `workerdomains`) в узкую область не попадают — они известны только
  приложению пользователя, а служба обхода одна на компьютер. Для них нужна область «все приложения».

## [2.1.0] — 2026-11-26

- **Движок прокси переписан с Python (PyInstaller) на C# (.NET 10) и встроен в приложение.** Отдельный
  `tgws-engine.exe`/`tgws-engine` больше не собирается и не устанавливается: MTProto-over-WebSocket
  (obfuscated2-рукопожатие, AES-CTR, пул WebSocket к дата-центрам, запасные пути через Cloudflare Worker,
  Cloudflare HTTP/2 для медиа и прямой TCP) работает в процессе окна. Это убирает запуск Python-интерпретатора
  и PyInstaller-загрузчика, лишний процесс и GIL, ускоряет старт прокси и снижает потребление памяти.
- `tgwsone --start` без запущенного окна поднимает тот же самый нативный файл в режиме `--engine`; если окно
  запущено, команды `--start`, `--stop` и `--status` идут в него через локальный канал. Значок в трее, автозапуск,
  остановка прокси при выходе и смена порта при занятом порте работают как раньше.
- Установщик MSI, архив для Linux и PKGBUILD ставят один исполняемый файл; правило брандмауэра для телефона
  теперь относится к `TgwsOne.exe`.
- Тесты движка (`tests/TgwsOne.Engine.Tests`): криптография AES-CTR и obfuscated2, разбор пакетов abridged/
  intermediate/padded, WebSocket-кадры, домены Cloudflare, сквозной обмен через запасной TCP-путь и хост
  движка внутри процесса.
- `tgwsone --engine …`, запущенный вручную, записывает себя в `engine.pid`: `--status` видит его, `--start` не
  поднимает второй, `--stop` останавливает. Раньше такой движок был никем не учтён: `--stop` отвечал «не был
  запущен» и оставлял его слушать.
- Окно пишет в журнал, почему не поднялся его канал управления (не создался сокет). Раньше эта ошибка терялась
  в фоновой задаче, а выход из приложения после неё заканчивался сбоем.
- `--host` и `--port` проверяются при разборе аргументов движка: имя вместо адреса или порт вне 1–65535 дают
  понятную ошибку, а не сообщение библиотеки при старте.
- Пул WebSocket: фоновая ротация читала общую таблицу соединений без блокировки; теперь работает только со своим
  бакетом.
- Криптография движка меньше нагружает процессор: keystream AES-CTR вырабатывается пачкой блоков за один вызов
  (чтение 64 КБ обрабатывается примерно в шесть раз быстрее), байты на линии не меняются.
- Рукопожатие obfuscated2 сверяется с векторами, вычисленными Python-библиотекой `cryptography` — той же, что в
  оригинале (`tools/obfuscated2-vectors.py`); поток AES-CTR — с независимым учебным эталоном.

## [2.0.1] — 2026-11-20

- Обход DPI по умолчанию касается только Telegram — того трафика, который идёт через прокси (TLS на 443 к хостам
  Telegram и Telegram Desktop). Остальные приложения больше не затрагиваются: профиль «все адреса Cloudflare»
  включается отдельным переключателем «Применять и к остальным приложениям» на странице «Обход DPI».
- Область обхода хранится в состоянии службы (`scope=telegram|all`); файл без этого ключа читается как «только Telegram»,
  а неизвестное значение никогда не расширяет обход.
- Тесты: устранён флейк UI-стенда `BypassRig` (ждал два снимка монитора, которых могло быть один).
## [2.0.0] — 2026-11-20

Приложение переписано заново; появилась версия для Linux.

- **Новое окно**: разделы «Главная», «Обход DPI», «Диагностика», «Журналы» и «Настройки». Одна кнопка
  «Подключить» запускает прокси и включает обход, «Отключить» останавливает свой прокси. Тема — как в системе,
  значок в трее, мастер первого запуска, подбор стратегии, диагностика с понятным вердиктом, уведомления о сбоях.
  Раздача прокси в домашнюю сеть: ссылка и QR-код для телефона.
- **Обход DPI на zapret2.** По умолчанию режим «Авто»: для каждого узла сам подбирается лучшая из четырёх встроенных
  стратегий, и видно, какая сработала. Исключения (узлы и адреса, которых обход не касается) правит любой
  пользователь прямо в приложении; свои стратегии на Lua сохраняет администратор.
- **Администратор ставит один раз — пользователь работает без прав администратора и без запроса UAC.** Обходом
  владеет всегда работающая служба (Windows: `TgwsOneZapret` от имени SYSTEM, Linux: `tgwsone-zapret` в systemd),
  а приложение управляет ею через локальный канал.
- **Версия для Linux**: архив `tgwsone-2.0.0-linux-x64.tar.gz` с `install.sh` и `uninstall.sh`, а для Arch Linux —
  пакет `tgwsone-bin` (PKGBUILD).
- **Установщик Windows** заменяет 1.x при обновлении. Служба и правило брандмауэра для телефона (входящие
  соединения только из своей подсети и только в частной сети) ставятся самим MSI, без дополнительных действий,
  и удаляются вместе с программой. Настройки и исключения в `ProgramData\TgwsOne` при удалении остаются.
- **Windows 10 1809 и новее, в том числе без обновлений.** Из программы выключена аппаратная защита стека (CET):
  иначе .NET 10 вообще не запускается на Windows 10 без свежих обновлений (ошибка «Your Windows doesn't fully
  support CET» и тишина вместо окна). Цена — у самого процесса нет этой дополнительной защиты.
- Командная строка: `--zapret status | on | off | use <стратегия> | strategies | exclusions`, `--start`,
  `--stop`, `--status`, `--selftest`, `--version`.
- Исправлено относительно 1.x:
  - при чистой установке MSI не создавал задачу обхода — теперь службу ставит сам MSI;
  - смена стратегии не действовала в режиме «для всех пользователей»;
  - у прокси была вторая иконка в трее и окно первого запуска от движка — движок теперь работает без окон;
  - новый секрет не применялся к уже запущенному прокси, и Telegram переставал работать до ручного перезапуска;
  - секрет из 32 символов, но не из шестнадцатеричных, принимался, и движок отказывался запускаться;
  - при занятом порте приложение могло «переехать» на тоже занятый порт, когда свободного не находилось;
  - окно подвисало, пока приложение ждало ответа в основном потоке;
  - чужие процессы с таким же именем принимались за свои — теперь процесс узнаётся по файлу с номером процесса,
    времени запуска и пути;
  - загрузки из upstream не были закреплены — теперь версии и контрольные суммы движка и zapret2 зафиксированы.

## [1.0.5] — 2026-11-18
